# Local MPI job for CT-scan fracture meshes

This directory runs the elastic 3D phase-field fracture model used by
`pygalmesh/data/scripts/011-Fracture-From-CT-Scans` inside the dolfinx-alex
container.

The Eshelby tensor is assembled directly as a UFL expression. It is not
interpolated or projected before evaluating the J-integral. The simulation is
fixed to linear finite elements (`element_order=1`).

## Run from the host (recommended)

The wrapper accepts an arbitrary host mesh path and mounts only its directory
read-only at `/input` in a fresh container:

```bash
cd shared/scripts/068-ct-scan-fracture-local
PROCESSOR_NUMBER=8 ./run_in_container.sh \
  /Users/alexanderschluter/Work/Hypo/Hypo/Simulation/Meshing/pygalmesh/data/scripts/011-Fracture-From-CT-Scans/00_results/JM-25-74_Bin4_reduce-2_segmented_cluster_fine/JM-25-74_Bin4_reduce-2_segmented_cluster_fine_3D/subvolume_x52_y74/dlfx_mesh.xdmf
```

It uses the `alex-dolfinx` service from the repository's `docker-compose.yml`.
The normal `shared:/home` bind mount means the results remain available on the
host after the container exits.

## Run inside the container

Pass an XDMF mesh whose matching HDF5 file has the same basename and resides
beside it:

```bash
cd /home/scripts/068-ct-scan-fracture-local
PROCESSOR_NUMBER=8 ./run_local.sh
```

The example `dlfx_mesh.xdmf` and `dlfx_mesh.h5` are already available inside
the container under `/home/scripts/068-ct-scan-fracture-local/input_mesh/`.
Calling `run_local.sh` without a mesh argument selects this mesh. To use a
different mesh that is visible inside the container, pass its XDMF path as the
first argument.

The launcher reads exactly the XDMF file passed to it. For meshes generated by
`011-Fracture-From-CT-Scans`, pass `dlfx_mesh.xdmf` together with its sibling
`dlfx_mesh.h5`. This is the DOLFINx-native mesh created by
`make_mesh_dlfx_compatible.py`; the earlier `mesh.xdmf` is the meshio/meshing
output from which it is produced.

The default is four MPI processes. Select another number with:

```bash
PROCESSOR_NUMBER=8 ./run_local.sh /path/to/mesh.xdmf
```

Simulation parameters can also be supplied through the environment:

```bash
PROCESSOR_NUMBER=8 \
LAM=1.0 MU=1.0 GC=1.0 EPSILON_FACTOR=20.0 \
./run_local.sh /path/to/mesh.xdmf
```

Without elastic material options, the legacy defaults are `LAM=1.0` and
`MU=1.0`, equivalent to `E=2.5` and `nu=0.25`. To use the real-material
presets from `pygalmesh/009-Binning-Variation-CT-Stiffness`, select one of:

| `MATERIAL` | `E` [MPa] | `nu` |
|---|---:|---:|
| `am` | 73000 | 0.36 |
| `std` | 70000 | 0.35 |
| `conv` | 82000 | 0.35 |
| `ad` | 82000 | 0.35 |

For example:

```bash
PROCESSOR_NUMBER=8 MATERIAL=am GC=1.0 \
./run_local.sh /path/to/dlfx_mesh.xdmf
```

The Lamé parameters are computed from
`mu = E/[2(1+nu)]` and `lambda = E*nu/[(1+nu)(1-2nu)]`. Alternatively, pass
either direct Lamé parameters or a custom pair of engineering constants:

```bash
LAM=69012.60504201679 MU=26838.235294117647 ./run_local.sh

YOUNGS_MODULUS=73000 POISSON_RATIO=0.36 ./run_local.sh
```

Do not combine these input modes. With millimetres for the mesh and MPa for
the elastic parameters, use a consistently converted `GC` in N/mm.

Each execution creates an isolated timestamped directory below `results/` and
copies the mesh there before starting MPI. Open MPI running as root in a
container and local oversubscription are handled automatically. Every new run
also writes a human-readable `parameters.txt` in the same `key=value` format
as the 046 templates, plus the machine-readable `run_parameters.json`.

## Evaluate the results

Inside the running container, generate the same six publication-ready plot
families as in `pygalmesh/011` with:

```bash
cd /home/scripts/068-ct-scan-fracture-local
python3 evaluation.py
```

From the host, the equivalent convenience command is:

```bash
cd shared/scripts/068-ct-scan-fracture-local
./evaluate_in_container.sh
```

By default, the evaluator processes every run below `results/` that contains a
`pfmfrac*_graphs.txt` file. Each run is evaluated separately and its plots are
written into that run's own result directory. Explicit graph-file arguments can
select individual runs. It writes normalized and non-normalized versions of
`J_x` versus the measured crack-tip position, its monotonic envelope, and time.
Every figure is exported as PNG, PDF, and LaTeX-ready PGF. For normalized
plots, the specimen dimensions are read directly from the copied
`dlfx_mesh.xdmf`; new runs also record `G_c` in `run_parameters.json`. The
normalized plot labels use the 046 notation
`J_x/G_c^num`; this is a label change only and does not introduce an additional
numerical correction factor. The plots use the Computer Modern font and math
style of the 046 evaluation. Crack-tip plots use the physical mesh coordinate
`x_tip` directly in millimetres instead of dividing it by `L`. The normalized
time scale uses the specimen height `y_max - y_min` explicitly, so the symbol
`L` is no longer used in the plot labels.

In every crack-tip plot, the measured position is shifted by its first finite
value so that the curve starts at zero. The interval
`10 mm < x_tip < 45 mm` is highlighted.

The existing legacy local run used the default `G_c=1.0`. To set or override
`G_c` explicitly for all selected curves, use for example:

```bash
python3 evaluation.py --gc 1.0
```
